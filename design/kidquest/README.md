# KidQuest design workspace

Owner: ui-ux-designer. Layout follows pipeline §14.1. Everything here is **low fidelity and graybox**. Nothing is production UI or production art.

**Consistency with the existing app (pipeline §8.2a, product-owner constraint, 2026-11-22).** KidQuest is part of the Kids Math Quiz. Its shell uses the app's own tokens and layout from `static/css/{base,home,quiz,stats}.css` and `app/web/templates/`:
- the dark navy page;
- a quiz-style header card;
- the workspace with a tab row;
- the question card, owl tutor and keypad;
- the quiz popups;
- the per-child blue or purple accent.

Only the world canvas keeps natural, light art, and the Kampung, Kerajaan and Kota themes skin only that canvas. The mapping is in [`components/README.md` §5](components/README.md#5-consistency-with-the-existing-app); side-by-side renders are in [`wireframes/renders/compare-360-*.png`](wireframes/README.md#3-consistency-renders).

### Regenerate the art (design-time only)

The committed WebP files are the runtime source of truth; the app and the test suite never need Pillow.
To change the art, use a separate environment with the pinned asset tooling:

```bash
python3.12 -m venv .venv-assets
.venv-assets/bin/pip install -r requirements-assets.txt      # Pillow 10.4.0 (libwebp 1.4.0 wheel), numpy 1.26.4
.venv-assets/bin/python design/kidquest/tools/generate_golden_assets.py          # exports + manifests + source records
.venv-assets/bin/python design/kidquest/tools/render_proofs.py                   # proofs, templates, graybox, gallery data
.venv-assets/bin/python design/kidquest/tools/generate_golden_assets.py --check  # byte-for-byte reproducibility
node design/kidquest/gallery/capture-gallery.mjs                                 # gallery screenshots (Chrome)
```

Another Pillow/libwebp build gives the same pixels but may give different WebP bytes (Anaconda's
libwebp 1.3.2 differed on one road mask); `--check` reports that. Commit only what the pinned environment produces.

### Validate

```bash
.venv/bin/python scripts/validate_kidquest_assets.py              # pixel checks via Pillow or `dwebp` (brew install webp)
.venv/bin/python scripts/validate_kidquest_assets.py --structural-only   # no decoder available
```

The validator has no Pillow dependency: it parses WebP headers with the standard library and decodes
pixels with Pillow if present, otherwise with libwebp's `dwebp`. Tests that need a decoder (or Pillow to
craft bad images) skip with a reason when it is missing.

### Open the gallery

Open `design/kidquest/gallery/index.html` from `file://`. Query parameters: `?theme=kingdom&cell=38&onion=1&grid=1`.

## KQ-029: building extraction and QA (status: IN_REVIEW)

The six fixed 512 × 512 slots in each approved theme atlas are exported losslessly with libwebp.
The extractor validates the KQ-025 contract first, extends each runtime manifest, records the source
atlas/provenance, and verifies a zero-difference RGBA decode round trip.

```bash
PYTHONPATH=. .venv/bin/python design/kidquest/tools/extract_building_sprites.py
PYTHONPATH=. .venv/bin/python design/kidquest/tools/extract_building_sprites.py --check
PYTHONPATH=. .venv/bin/python scripts/validate_kidquest_assets.py --profile buildings
node design/kidquest/gallery/capture-kq029.mjs
```

The WebP profile is `cwebp -lossless -exact -m 6 -metadata none`. The `--check` command regenerates
all 18 sprites, three manifests, three source-map records, and `gallery/kq029-data.js` in temporary
storage and requires byte-identical committed outputs. Open `gallery/kq029.html` for the cross-theme
geometry and UI-state review matrix; captures are under `gallery/screenshots/`.

# KQ-008 — Implement Q001 challenge and answer flow

## Outcome

A child can start Q001, answer its math challenges, receive supportive retry feedback, and earn the starter reward exactly once.

## Scope

1. Implement quest start/resume and deterministic challenge generation for Q001.
2. Implement atomic answer submission with server-owned correctness and idempotency.
3. Apply retry/hint behavior, daily limits, progress, starter materials, and starter blueprint rules from the PRD.
4. Preserve calm resume across interrupted sessions.
5. Add correctness, retry, limit, duplicate, rollback, and concurrency tests.

## Deliverables

- Quest/challenge/answer services and APIs.
- Reward/progress ledger entries required by Q001.
- Contract and concurrency test coverage.

## Acceptance criteria

- [x] The server never exposes the correct answer before submission.
- [x] Wrong answers do not punish or reset earned progress and offer the specified support.
- [x] Q001 completes only after its defined success conditions.
- [x] Starter reward and blueprint are granted once under retries and concurrency.
- [x] Daily limits use the Jakarta clock and return a clear resume state.

## Verification

- Run full tests and repeated concurrent duplicate-answer scenarios.
- Walk start → wrong answer → hint/retry → completion → duplicate retry and record API results.

## Out of scope

- Building placement, Wallet conversion, XP economy, and later quests.

## Completion handoff

- **Summary:** Q001 is playable through the API: start/resume, one non-leaking active challenge, and an atomic, idempotent answer. Wrong answers record one attempt and one daily use, give the neutral hint and then the worked example, and never change rewards or status. The Jakarta daily cap blocks new answers with a reset time while replays and world inspection keep working, and usage resets at Jakarta midnight. KidQuest attempts never change legacy statistics.

# KQ-009 — Implement Q001 building placement

## Outcome

A child can preview and place the starter house once, with all costs, ownership, geometry, and world-version rules enforced atomically.

## Scope

1. Implement placement preview validation for zone, footprint, collision, inventory, blueprint, quest, and version prerequisites.
2. Implement one atomic placement command that consumes required resources and creates the building.
3. Enforce the unique core-building rule at both service and database levels.
4. Return precise, child-safe failures without partial consumption.
5. Add boundary, collision, duplicate, stale-version, rollback, and concurrency tests.

## Deliverables

- Placement validation/service and API contract.
- Atomic cost/ownership/building persistence.
- Placement regression and concurrency tests.

## Acceptance criteria

- [x] Invalid placement never consumes resources or blueprint ownership.
- [x] Valid placement creates exactly one starter house at an allowed coordinate.
- [x] Concurrent placement requests cannot create duplicate core buildings.
- [x] Theme selection does not affect geometry validation.
- [x] A stale world version returns a refreshable conflict response.

## Verification

- Run full and placement-specific tests.
- Exercise every invalid reason and one concurrent valid placement on a disposable database.

## Out of scope

- Production UI, moving buildings, roads, and productive income.

## Completion handoff

- **Summary:** The starter house can be previewed (read-only) and placed once. Placement is one transaction: idempotency, world version, the shared pure rules (quest READY_TO_BUILD, blueprint, rotation 0, bounds, fixed objects, other buildings and roads, water, `tutorial_zone`, wood), then building row, 4-wood ledger spend, Q001 COMPLETED, and world-version bump. Every failure leaves the database untouched and returns a machine-readable rule with an Indonesian message. Duplicate core buildings are stopped by the service and, independently, by the DB index. Concurrent placements (50× per scenario) always yield one house and one spend; losers get the refreshable version conflict. Geometry validation is identical in all three themes. Q001 is now playable end to end through the API.
- **Files changed:** new `app/domain/kidquest/placement.py`, `tests/integration/kidquest/test_placement.py`; edited `app/services/kidquest_service.py`, `app/api/kidquest_routes.py`, `app/api/kidquest_schemas.py`, `app/db/kidquest_repo.py`, `tests/integration/kidquest/{conftest,test_concurrency,test_state_api,test_feature_gating}.py`; this packet and the tracker row.

# KQ-004 — Add KidQuest domain, content, and Migration 8

## Outcome

KidQuest has a validated, data-driven domain model and persistence foundation for world state, themes, quests, buildings, roads, and placement.

## Source references

- [Implementation plan — M3](../KidQuest_Implementation_Plan.md)
- [PRD — world, building, road, and theme specifications](../KidQuest_Build_Your_World_PRD_v1.4.md)
- [Visual pipeline — asset identifiers and geometry](../KidQuest_Visual_Design_Asset_Pipeline.md)

## Scope

1. Define stable IDs and schemas for themes, resources, buildings, quests, zones, footprints, anchors, and 16 road masks.
2. Add versioned content files for the approved core catalog and Q001 layout.
3. Implement Migration 8 for KidQuest state needed by the first playable slice.
4. Add database constraints, including the partial uniqueness rule for each core building.
5. Build content validation that fails on missing references, illegal geometry, or incomplete theme mappings.

## Deliverables

- Domain types/constants and versioned content catalog.
- Migration 8 and migration tests.
- Content/schema validator and Q001 seed definition.

## Acceptance criteria

- [x] Empty and existing databases migrate forward without losing legacy data.
- [x] Re-running migrations is safe.
- [x] Every content ID is stable, unique, and referenced through data rather than display text.
- [x] Geometry, footprint, anchor, road-mask, quest, and theme references validate automatically.
- [x] Database constraints prevent duplicate core-building ownership where required.
- [x] Building footprints match the KQ-025 sprite-map contract (2×2 house/garden/bakery/park, 1×2 bridge with long axis north–south, 1×1 market stall), and `pulau_tunas_v1` defines `bridge_zone` as 1 wide × 2 tall.

## Verification

- Run migration tests from empty and legacy fixtures.
- Run the content validator and record catalog counts and validation output.

## Out of scope

- API endpoints, frontend screens, final art, economy wallet, or cash-out tables.
